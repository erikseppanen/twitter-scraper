Your X likes, saved on a Mac you own.

A private, searchable archive of everything you've liked on X (Twitter), including the photos, videos and long articles. It updates itself every four hours on an always-on Mac, and you browse it from your phone or laptop through a private link.

A quick tour

The app works the same on a laptop and a phone, in light or dark mode.

Screenshots use a made-up archive with fictional accounts. They're generated from the real app by npm --prefix service run screenshots.

Why keep your own copy?

Likes are a good record of what caught your attention, but X only gives you an endless scroll. Tweets get deleted, accounts go private, and images disappear. Search across your own likes is limited.

  • It's yours. Tweets, media and articles are plain files on your Mac. No database and no cloud service.
  • It keeps going. A background service checks for new likes every four hours. You don't run anything by hand.
  • It's private. Only someone with your private link can open the archive. Search, related tweets and translation run on your Mac, not on an AI service.
  • No API key. It uses your own X sign-in in a separate Chrome profile, plus public tweet-content endpoints.

What you get

A web app laid out like X, with Likes, Explore, Random and Updates in the menu (or a tab bar on phones).

Search text, authors and article titles. Filter by year, month or author. Sort newest, oldest or shuffled. Your filters stay in the address, so links keep them.

How it works

One Mac stays on and does everything. Your other devices only view.

  1. Every four hours, or when you tap Update now, the Node service opens Chrome in the background with its own profile, where you signed into X once.
  2. It scrolls your Likes page until it reaches the last like it saw. It goes by the order you liked things, so a 2015 tweet you liked today still counts as new.
  3. The Clojure importer fetches each tweet's text, quoted tweet, article and media into a copy of the archive.
  4. If every new tweet has content, the copy replaces the live archive, and the old version is kept for rollback. If anything is wrong, the live archive stays as it was.
  5. Your phone opens the app through a Tailscale HTTPS address. A private bookmark signs it in.

What you need

This is a self-hosted tool for people comfortable with a terminal. Setup takes an hour or so. After that you shouldn't need the terminal.

  • A Mac with Apple Silicon that stays onA Mac Mini is ideal. The service runs while you're logged into macOS. Staging uses APFS copy-on-write, so Linux isn't supported.
  • An X accountYou sign in once in a dedicated Chrome window. Your normal browser isn't touched.
  • HomebrewFor Node.js, Java 21, the Clojure CLI, Python 3 and Google Chrome.
  • TailscaleGives the Mac an HTTPS address. Use Serve for tailnet-only access, or Funnel to view from any device.
  • Disk space for mediaVideos add up. A few thousand likes with media can take several gigabytes.
  • Optional: your X data exportTo import likes from before the first automatic update.

Install

Run these on the Mac that will host the archive. The full guide, with upgrade and recovery details, is in service/README.md.

  1. Install the tools

    Java 21 from Homebrew isn't on your PATH, so typing java won't find it. That's expected; the service points to it directly.

    brew install node openjdk@21 clojure/tools/clojure python
brew install --cask google-chrome

    Install Tailscale and sign in.

  2. Get the code

    git clone https://github.com/erikseppanen/twitter-scraper.git ~/twitter-scraper
cd ~/twitter-scraper

  3. Give the Mac an HTTPS address

    The service only listens on 127.0.0.1:4318. Tailscale puts HTTPS in front of it. Pick one:

    # Only your own devices running Tailscale can reach it
tailscale serve --bg http://127.0.0.1:4318

# Or reachable from any device (still needs the private link to get in)
tailscale funnel --bg --https=8443 http://127.0.0.1:4318

  4. Run the installer

    Use your Mac's Tailscale address, including the port if you chose 8443. The installer downloads dependencies, runs every test, builds the app and registers a LaunchAgent that starts the service at login and restarts it if it crashes.

    PUBLIC_ORIGIN=https://YOUR-MAC.YOUR-TAILNET.ts.net bash scripts/install-mini.sh

    It leaves a Twitter Archive bookmark on the desktop. That bookmark is your private link.

  5. Sign into X once

    Open the bookmark, go to Updates, choose Reconnect X, sign in in the Chrome window that opens, then choose Finish sign-in. The first update starts on its own.

  6. Optional: import your older likes

    Download your data from X, extract it, and import it into a separate folder first. See the tutorial for moving it into place.

    clj -M -m twitter-scraper.core --input ~/twitter-export --output ./archive-repair

  7. Open it on your phone

    Send the private link (in .service/private-link.txt) to your phone privately, open it once, and bookmark the app. It signs you in and removes the secret from the address bar.

Treat the private link like a password. Anyone who has it can view your archive and use its controls. There are no separate user accounts. You can replace the secret at any time; see Access.

Never commit or upload .service/. It holds the secret and your X session.

Day to day

Mostly, you just open the bookmark.

  • Updates are automatic every four hours. Tap Update now on the Updates page if you want them sooner.
  • If X signs you out, Updates says so. Choose Reconnect X, sign in on the Mac, then Finish sign-in.
  • After a reboot, log into the Mac's macOS account so the service can start.
  • Back up all of archive/, including its hidden .tweet-cache.edn, media/ and articles/. Media whose source is deleted can't be downloaded again.

Good to know

Honest limits, so there are no surprises.

Will it get every like I've ever made?

Automatic updates collect new likes from where they left off. They aren't a full historical backfill: X's Likes page stops loading eventually. For older likes, import X's data export.

What happens when X changes its site?

Collection reads the Likes page in a real browser, so X page changes, login challenges or rate limits can break an update until the code is fixed. A failed update never touches your existing archive, and Updates shows what went wrong.

Does anything get sent to an AI service?

No. Related tweets and Explore use a small embedding model (MiniLM), and translation uses NLLB. Both run on your Mac. Their weights download from Hugging Face the first time. Matching works best in English.

Can I run it on Linux, Windows or a server?

Not as-is. The installer and the copy-on-write staging target macOS on APFS, and sign-in needs a visible Chrome window.

Deleted or protected tweets?

Tweets that were already gone when the importer reached them can't be recovered. Once a tweet is archived, its text and media stay even if the original is deleted.
